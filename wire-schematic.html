The legs

Status is the shipped default with no flags passed. Where it is conditional, the condition is named.

L1
Client ↔ hbbs · rendezvous
TCP 21116 · protobuf
XSalsa20-Poly1305. Key chosen by the client, sealed to the server's per-connection ephemeral. Client proves a pinned device key bound to its peer id.
Encrypted
L2
Client → hbbs over UDP
UDP 21116
No handshake exists for a datagram socket. Refused by default on both ends — --udp-registration=N, client disable-udp=Y.
Refused
L3
hbbs → client · pushes
rides the peer's own L1 connection
Punch instructions, forwarded relay requests, local-address fetches. Sealed with that connection's key. Falls back to plaintext UDP only for a UDP-registered peer — unreachable at defaults.
Encrypted
L4
Client ↔ client · the session
punched TCP / KCP-over-UDP / IPv6
Screen, input, audio, clipboard, files. Two-level Ed25519 chain. The password never crosses the wire. Downgrades to plaintext on a handshake fault — see gap 2.
Conditional
L5a
Client ↔ hbbr · control frame
TCP 21117
Its own signed key exchange, separate key. Covers the relay request — the licence key and both peer ids — then both ends drop the cipher. Fail-closed.
Encrypted
L5b
Client ↔ client through hbbr
TCP 21117 · byte pump
Exactly one layer, and it is the end-to-end one. hbbr sees ciphertext and cannot read video, audio, clipboard or files. No double encryption, so relaying costs a hop — not CPU.
Inherits L4
L6
Direct IP / host:port
TCP · off by default
No handshake, no cipher, no authentication. Currently also non-functional — the controlled side waits for a key that never arrives. The one place where "fast" and "encrypted" diverge.
Plaintext
L7
Client ↔ management API
HTTPS 21120
Two layers. Login and the policy poll are sealed inside TLS and survive a TLS-stripping attacker. Address book and heartbeat are TLS-only, and that TLS authenticates nothing unless the certificate is pinned.
Conditional
L8
hbbs → LDAP / AD
LDAPS 636
ldaps:// enforced; plaintext ldap:// is refused outright. Certificate verification on unless explicitly disabled.
Encrypted
Handshakes

How each key is established

Three exchanges carry everything. Each ends with a fresh symmetric key and a nonce whose byte 8 separates the two directions, so the two sides never share keystream.

L1

Rendezvous

←hbbs · KeyExchange{ Ed25519_sign(ephemeral_X25519_pub) }
public by design
→client · NemoClientAuth{
  client_box_pk,
  sealed_key = box_seal(K‖0x01),
  device_pub, peer_id,
  sig = Ed25519(ctx ‖ server_eph ‖ … ‖ peer_id)
}
⇄XSalsa20-Poly1305 under K

The signature covers the server's per-connection ephemeral, so a captured proof is useless on any other connection. Freshness from a live challenge — no clock involved.

L4

Peer to peer

←controlled · SignedId{ Ed25519_sign(IdPk{ id, eph_X25519 }) }
·controller verifies with the peer key hbbs signed and handed over in the punch response
→controller · PublicKey{ box_seal(K‖0x01) }
⇄screen · input · audio · clipboard · files

Two-level chain: hbbs signs the peer's identity key, the peer signs its own ephemeral. The login password is hashed twice with a salt and a challenge — it never crosses the wire in any form.

L5

Through the relay

←hbbr · KeyExchange{ Ed25519_sign(ephemeral) } — its own key
→client · sealed K, then RequestRelay{ licence_key, id, uuid }
·both ends drop the cipher, keep the framing
⇄L4 ciphertext, pumped byte for byte

The control frame is protected so the licence key and both peer ids are not exposed to the path. After that hbbr is a pipe — it holds no key that could open the session.

The question

Is everything encrypted?

No — but the gaps are now specific, not structural.

Encrypted unconditionally at shipped defaults: rendezvous signalling, server pushes, the relay control frame, the relayed payload, LDAP, and the management API's login and policy poll. Nine things remain, ranked by what would actually hurt.

Port-forward and RDP tunnels are plaintext After login both ends drop the cipher and the framing. An entire RDP session — credentials included — crosses the punched link, or the relay, in the clear. always · every transport · the worst one
The session downgrades on a handshake fault One corrupted frame from an on-path attacker yields a fully plaintext session, because the fail-closed switch is a policy key rather than the default. nemo-require-encrypted-session defaults off
Short frames bypass decryption entirely Frames of one byte or less skip the cipher and do not advance the receive counter, so they are unauthenticated on every otherwise-encrypted leg. The rendezvous loop treats an empty frame as a keep-alive and echoes it. always · inherited from upstream
LAN discovery broadcasts who you are Id, hostname, the active username, platform and MAC, broadcast to the whole subnet. enable-lan-discovery is on by default
Public STUN queries leave the network Every connect attempt queries Google, Cloudflare and Nextcloud STUN servers in the clear — announcing that this site exists, on a network meant to be private. enable-udp-punch is on by default
Port 21115 answers anyone An unauthenticated caller can enumerate which TBFDesk ids are currently online. always, wherever 21115 is reachable
The UDP software-update arm replies to anything Any datagram gets an unencrypted reply carrying the configured update URL — regardless of whether UDP registration is refused. always · independent of --udp-registration
The management API binds loopback as HTTP TLS keys off routable or LDAP-enabled, so on the default loopback bind the admin bearer token crosses the interface in the clear — reachable by any local process or an SSH tunnel. default bind 127.0.0.1:21120 with LDAP off
The direct-IP path enforces nothing Dead rather than dangerous today — the controlled side waits for a key that never arrives — but nothing on the controller requires encryption if that ever changes. direct-server is off by default
